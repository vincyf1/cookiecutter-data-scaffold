## Agentic self-healing

When a batch DAG task fails, a healing task runs an AI agent that reads the
failure logs, diagnoses the root cause, and writes a patch for you to review.

### Try it

Trigger the demo DAG with the failure injected:

```bash
docker compose up -d airflow-standalone
# In the Airflow UI, trigger example_events_dag with config:
#   {"failure_mode": "schema_drift"}
```

`extract` emits a record keyed `customer_name` instead of `name`. `load` turns
each record into an `Event` before writing it, so it raises `SchemaDriftError`
naming the missing field, the undeclared one, and the fields the contract in
`src/{{ cookiecutter.project_slug }}/events.py` declares. This works with or
without the Lakehouse Pattern.

The `load` task fails, the `heal_on_failure` task runs, and you get, under the
project root:

- `artifacts/<trace_id>.patch` — a unified diff, ready to `git apply`
- `artifacts/<trace_id>.json` — the proposed PR title, body, and confidence
{%- if cookiecutter.include_lakehouse %}
- a row in the `agent_traces` DuckDB table holding the full run as a JSON array
{%- else %}
- `artifacts/traces/<trace_id>.json` — the full run as a JSON array
{%- endif %}

`docker-compose.yml` bind-mounts `./artifacts` and `./logs` so both the patch
and the log the agent read stay visible on the host. The image runs as uid
50000, which on Linux cannot write to those host-owned directories, so an
`airflow-init` service runs first as root and chowns them to the uid airflow
will use. That runs on every `docker compose up`, including a fresh clone, so
there is no manual step.

Generation also pinned this machine's uid in a gitignored `.env` beside
`docker-compose.yml`. That is a convenience, not a requirement: with it, the
chown is a no-op and the logs and patches stay owned by you instead of by uid
50000. On a different machine, refresh it to keep that property:

```bash
echo "AIRFLOW_UID=$(id -u)" > .env
```

Nothing is applied automatically. The agent proposes; you merge. With
`AGENTIC_GITHUB_REPO` set, the patch is pushed to an `agentic/heal-*` branch and
opened as a pull request, so CI runs it before anyone reviews it. That is why the
agent can only patch files under `src/` and `transformation/`, never workflows,
tests or dependency pins.

### Configuration

| Variable | Purpose |
| --- | --- |
| `ANTHROPIC_API_KEY` | Required for live runs. The default test suite does not need it. |
| `AGENTIC_GITHUB_REPO` | Set to `owner/repo` to open real pull requests instead of writing local patches. Requires push credentials and an authenticated `gh`. |

The agent's tools are limited to reading the task log, reading a file inside
the project root (never `.git/` or credential files), and staging a
single-occurrence replacement under `src/` or `transformation/`. It cannot run
shell commands or write to disk.

Edit the diagnosis prompt at `src/{{ cookiecutter.project_slug }}/agentic/prompts/diagnose.md`.

### Evals

```bash
uv run pytest evals/                # deterministic; no API key needed
uv run pytest evals/ -m live        # runs the real model
uv run pytest evals/ -m graded      # runs the model, then grades the run
```

report to `evals/reports/`.

## Event ingestion

Batch and Streaming write validated, immutable `Event` values through the
context-managed `EventSink` interface. Use `create_event_sink(destination)`
with an explicit `Path` to select a destination.

{% if cookiecutter.include_lakehouse %}
The DuckDB adapter owns one connection per context and commits each batch as
one transaction, rolling back the batch on an insert failure. Both ingestion
patterns default to `lakehouse.duckdb`.
{% else %}
The Parquet adapter publishes one immutable `part-<id>.parquet` file per nonempty
batch. Files are written to a temporary path and renamed only after success.
Defaults are `data/events/batch/` and `data/events/streaming/`.
{% endif %}

{% if cookiecutter.include_batch %}
The Airflow load task opens one sink per task run and validates records before writing.
{% endif %}
{% if cookiecutter.include_streaming %}
The Kafka consumer opens one sink for the consumer lifetime, skips malformed events,
and closes its resources on exit. Storage failures propagate to the caller.
{% endif %}
{% endif %}
